# 项目技术说明

## 整体架构

本项目是一个对话式 Agent 应用，由三部分组成：

- **Agent 层**（`agent/`）：基于 LangChain v1 的 `create_agent` 构建 ReAct Agent，
  目前挂载四个工具——数学计算、当前时间、联网搜索、知识库检索。
- **服务层**（`server/`）：FastAPI 提供 JWT 认证、SSE 流式对话、Redis 会话存储，
  用户表与审计日志存放在 MySQL 8（未配置 `DATABASE_URL` 时回落 SQLite）。
- **前端层**（`frontend/`）：Vue 3 与 Element Plus，通过 `/api` 代理访问后端。

## 关键运行参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 后端端口 | 8000 | uvicorn 默认监听端口 |
| 前端开发端口 | 5173 | vite dev server，容器部署时为 8080 |
| 会话 TTL | 7 天（168 小时） | Redis 中会话历史的过期时间，可通过 `SESSION_TTL_HOURS` 调整 |
| 历史条数上限 | 20 | 超过后裁剪，保证 tool 消息不脱离其 AI 消息 |
| Agent 超时 | 90 秒（带图片/附件 +60 秒） | 单次请求的最长执行时间 |
| JWT 有效期 | 7 天 | 由 `ACCESS_TOKEN_EXPIRE_MINUTES` 控制 |

## 工具说明

- `calculate`：基于 AST 白名单求值，**不使用 eval**。支持四则运算、幂运算、
  常用数学函数（sqrt、log、sin、factorial 等）、常量 pi/e/tau，
  以及 `sum(range(...))` 形式的求和。为防资源耗尽，限制了幂运算规模、
  阶乘上限，以及 range 序列长度不超过 100000 项。
- `get_current_time`：返回本地时间，格式为 `YYYY-MM-DD HH:MM:SS`。
- `web_search`：基于 Tavily 的联网搜索，默认返回 3 条结果。
- `search_knowledge_base`：检索本地知识库，返回带编号的引用片段。

## 知识库（RAG）配置

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| Embedding 模型 | BAAI/bge-m3 | 通过 SiliconFlow 的 OpenAI 兼容接口调用 |
| Rerank 模型 | BAAI/bge-reranker-v2-m3 | cross-encoder 精排 |
| chunk_size | 500 字符 | 分块目标长度 |
| chunk_overlap | 80 字符 | 相邻块重叠长度 |
| top_k | 4 | 最终返回给模型的条数 |
| 候选倍数 | 3 | 先召回 top_k × 3 条再精排 |
| 最低相关分 | 0.002 | 低于该分数的候选会被丢弃，该值由实测分数分布确定 |

检索采用**混合检索**：Chroma 负责向量召回，BM25 负责字面召回，
两路结果用 RRF（Reciprocal Rank Fusion）融合，再交给 cross-encoder 精排。

## 评测体系

评测数据集位于 `evals/dataset.jsonl`，覆盖 10 个类别：
单步计算、多步计算、时间查询、实时信息、无需工具、多轮对话、
多工具协作、Prompt Injection、边界用例、知识库问答。

**判定分三层**，三者全部通过才算该用例通过：

1. **工具调用是否正确** —— 该调的调了、不该调的没乱调
2. **最终答案是否正确** —— 数值与格式类用规则匹配，开放式与语义类交给 LLM-as-judge
3. **引用是否标注** —— 仅知识库问答用例要求，回答须带 `[编号]`，没有引用就无法核验是否忠实于原文

因为 LLM 输出存在随机性，同一份代码连跑多轮，失败集合可能完全不同，
正式结论需要 `--repeat 3` 以上，并关注**稳定通过率**而非单轮数字。

检索质量单独评测（`evals/retrieval_eval.py`），度量 Recall@k、MRR 与精排增益，
并可选测忠实度。与端到端评测分开的原因是：端到端失败时，
如果分不清是"检索没召回"还是"生成不忠实"，就只能靠猜去改。

## Agent 架构

项目保留两套可切换的 Agent 实现，用环境变量 `AGENT_ARCH` 选择：

- `react`（默认）：单 ReAct 循环，4 个工具全量挂载
- `graph`：LangGraph 显式图，先分类路由再并行执行专家节点

实测结论是当前规模下 `react` 更优——多 Agent 的路由环节本身会成为新的失败点，
且 P95 延迟翻倍。graph 实现保留在代码中，两者可用同一套数据集对比。
